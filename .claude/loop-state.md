## Key finding that shapes the plan

The issue assumes diff-size/iteration stats are "already tracked in `~/.shipwright/baselines/`". They are not. That directory holds the predictive EMA store (`default.json`, keys `<stage>.<metric>` → `{value,count,updated}`), and `scripts/lib/pipeline-state.sh:204-216` only writes `build.duration_s` / `test.duration_s`. Reading alone would ship a feature that can never fire, so the plan adds the write side (`build.diff_lines`, `build.iterations` on build-stage *completion*, so it stays a successful-pipeline baseline).

## Second finding: dedup must be on disk

`pipeline_compute_vitals` is polled from four call sites (`daemon-adaptive.sh:411`, `daemon-poll.sh:146`, `loop-convergence.sh:73`, `pipeline-execution.sh:213`). A process-local dedup flag would append an event per poll per job to `events.jsonl` — which `daemon-poll-health.sh:236` and `daemon-patrol.sh:702` read as `tail -200 | jq -s`, so a flood silently evicts `pipeline.completed` events and corrupts DORA metrics and auto-scaling. Dedup therefore lives in the per-issue progress file (`.anomaly_flagged`), written under the existing `_vitals_acquire_lock` with tmp+`mv`, and emission is suppressed entirely when there's no progress file.

## Shape of the change

- **`scripts/sw-pipeline-vitals.sh`** — `_vitals_baseline_value`, `_vitals_ratio_exceeds` (awk, baselines are EMA floats), dedup helpers, `_compute_anomaly`; an `anomaly` object added to the vitals JSON, a warning line in the dashboard, a `--anomaly` output mode. `current_diff` and `current_iteration` are already computed there — no new git calls on the poll path.
- **`scripts/lib/pipeline-state.sh`** — baseline recording, mirroring the existing `duration_s` block, `|| true`-guarded.
- **`scripts/sw-pipeline-vitals-test.sh`** — 10 new cases (both crossings, under-threshold, missing/malformed/zero baseline, `count<3` cold-start suppression, dedup, env override, CLI integration).
- **`.claude/CLAUDE.md`** — `vitals.anomaly_multiplier` / `anomaly_min_samples`, hand-written region only.

Three deliberate calls, documented in the plan: the anomaly does **not** feed `health_score` (that would move the daemon's gate at threshold 40 and the auto-scaler); `_smart_int` is used per-call rather than at source time so config/env changes take effect; and I rejected shelling out to `sw-predictive.sh anomaly` — it forks twice per poll (fork exhaustion is a recorded failure pattern here) and writes its own anomaly records and events, which makes dedup impossible.

The event type is `pipeline_vitals_anomaly` verbatim per the acceptance criteria, though it deviates from the repo's dotted `pipeline.*` convention.
