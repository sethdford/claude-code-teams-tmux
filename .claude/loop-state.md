# Plan: Iteration Waste & Stuck Loop Detector with Early Termination

## Context & Reasoning

### Existing Infrastructure (reuse, don't duplicate)
- `scripts/lib/loop-convergence.sh` already implements `detect_stuckness()` with 7 signals (text overlap, diff hash, error hash, exit code, repeated errors, diff size, iteration budget) and `record_iteration_stuckness_data()`.
- `scripts/sw-loop.sh` already calls `record_iteration_stuckness_data` per iteration and acts on `STUCKNESS_COUNT >= 3` (line 2518) by triggering session restart.
- `_smart_int "loop.<key>"` reads from `daemon-config.json` `loop.*` already.

### Gap vs. Issue Requirements
The issue asks for: configurable thresholds (`min_progress_threshold`, `circular_edit_window`, `semantic_similarity_threshold`), **circular file edit** detection (same file edited and reverted), **early termination** with structured diagnostic report, `waste_detected` event, dashboard metrics, CLAUDE.md docs.

Current code has hardcoded thresholds (overlap=90%, signals>=2, stuckness>=3), no circular-file detection, no structured diagnostic report file, and uses event name `loop.stuckness_detected`.

### Approach: Extend, Don't Replace
Add a thin layer (`scripts/lib/loop-waste-detector.sh`) that:
1. Wraps existing `detect_stuckness` with config-driven thresholds.
2. Adds new signals: circular file edits (window-based file path repetition), explicit semantic similarity threshold check.
3. Emits the canonical `waste_detected` event alongside the legacy event for back-compat.
4. Writes a structured `waste-report.json` artifact when early termination fires.
