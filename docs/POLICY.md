# Shipwright Policy Engine

Central configuration for all Shipwright tunables — timeouts, limits, thresholds, iteration caps, and convergence parameters.

## Override Precedence

Values are resolved in this order (first match wins):

```
1. SHIPWRIGHT_* env vars     (highest — operator override)
2. .claude/daemon-config.json (operator config)
3. .claude/policy-overrides.json (adaptive learning / per-repo overrides)
4. config/policy.json         (base policy — checked into repo)
5. config/defaults.json       (fallback values)
6. Function parameter default (last resort)
```

### Environment Variables

Any policy dotpath maps to an env var: `loop.max_iterations` becomes `SHIPWRIGHT_LOOP_MAX_ITERATIONS`.

### Policy Overrides

`.claude/policy-overrides.json` is generated by `shipwright adaptive suggest-overrides` from high-confidence adaptive learning data. It can also be manually edited for per-repo tuning.

To generate overrides from adaptive data:
```bash
shipwright adaptive suggest-overrides              # Write overrides
shipwright adaptive suggest-overrides --dry-run    # Preview without writing
shipwright adaptive suggest-overrides --min-samples 50  # Require more samples
```

To reset overrides:
```bash
rm .claude/policy-overrides.json
```

## Validation

### Doctor Checks

`shipwright doctor` includes a Policy & Schema section that:
- Validates `config/policy.json` is valid JSON
- Checks required sections exist (daemon, pipeline, quality)
- Runs `policy_validate` for numeric constraint checking
- Validates `config/policy.schema.json` has loop and decision definitions
- Checks `.claude/policy-overrides.json` if present

### Programmatic Validation

```bash
source scripts/lib/policy.sh
policy_validate config/policy.json    # Returns 0 on success, >0 on failure
```

The validator checks:
- Valid JSON
- Required top-level sections present
- Numeric values within schema-defined bounds
- Correct types for key fields

## Schema

`config/policy.schema.json` is a JSON Schema draft-07 document. It defines types, ranges, and required fields for all policy sections. Editors with JSON Schema support (VS Code, IntelliJ) get autocomplete and validation.

## Init-Time Loading Pattern

All `_config_get_int` calls happen at script initialization (top of file), not inside loops. This prevents spawning `jq` hundreds of times per pipeline run. Example:

```bash
# At script top (init time)
MAX_ITERATIONS=$(_config_get_int "loop.max_iterations" 20)

# NOT inside a loop
for i in $(seq 1 $MAX_ITERATIONS); do
    # ... use $MAX_ITERATIONS directly
done
```
